===============================================================================
1. CONTEXTO DO PROJETO
===============================================================================

RE.SOURCE e um ecommerce B2B academico para negociacao de residuos entre
empresas. O objetivo imediato nao e producao: e apresentar um MVP funcional no
curso. Existe a possibilidade de evoluir o sistema para producao futuramente.

Prazo de emergencia: seis dias de desenvolvimento.

Fluxo principal da demonstracao:

Cadastro
-> confirmacao de e-mail
-> login como empresa pendente
-> navegacao limitada
-> aprovacao pelo administrador
-> dashboard liberado
-> anuncio e chat
-> proposta e acordo mutuo
-> escolha de frete
-> confirmacao da entrega por codigo
-> liberacao de saldo
-> solicitacao de saque PIX/TED
-> aprovacao ou recusa administrativa

Regra acordada: antes de implementar qualquer mock, perguntar ao responsavel se
ele prefere a simulacao ou uma implementacao real.

===============================================================================
2. AMBIENTE E ARQUITETURA
===============================================================================

- Windows com XAMPP.
- Projeto esperado em C:\xampp\htdocs\re.source.
- PHP com arquitetura MVC propria.
- Entrada publica: public/index.php.
- Rotas: routes/web.php.
- Banco: MariaDB/MySQL via PDO.
- Banco principal configurado: resource.
- Configuracoes locais e segredos: .env.
- Modelo seguro de configuracao: .env.example.
- URL local base: http://localhost/re.source
- Painel administrativo: http://localhost/re.source/admin
- Empresas no admin: http://localhost/re.source/admin/empresas

O arquivo config/env.php carrega as variaveis de ambiente. A conexao fica em
config/conexao.php e usa resource como nome padrao. O SMTP fica em
config/mailer.php e le usuario e senha apenas do .env.

===============================================================================
4. BANCO DE DADOS
===============================================================================

Para preparar um banco novo chamado resource, importar nesta ordem:

1. database/seeders/re.sourcebanco.sql
2. database/inserts/create_admin.sql
3. database/inserts/empresa_demo.sql       (opcional)
4. database/inserts/produto.sql            (opcional; depende da empresa demo)
5. database/inserts/saldo_demo.sql         (opcional)

Para atualizar um banco anterior ao chat do Dia 2, executar tambem:

database/migrations/20260702_001_chat_indexes.sql

O arquivo abaixo deve ser usado somente para atualizar um banco antigo:

database/migrations/20260701_001_pending_and_admin_roles.sql

Ele nao precisa ser executado depois do schema completo em um banco novo.

Os SQLs foram testados em um banco limpo. Eles criaram 27 tabelas, empresas,
anuncios, negociacao financeira de demonstracao e usuarios com senhas bcrypt.
